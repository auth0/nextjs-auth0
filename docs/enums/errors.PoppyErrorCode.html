    INVALID_AGENT

    INVALID_AGENT: "invalid_poppy_agent"

    The ID token has a Poppy act but no valid sub or exp. The SDK refuses it rather than take the agent for a person. error.reason names the failing check; it is logged on the server and never part of the message.

    • Defined in src/errors/poppy-errors.ts:25

    INVALID_GUEST

    INVALID_GUEST: "invalid_poppy_guest"

    The ID token looks like a Poppy guest login (an anon_poppy@ subject or the anonymous sub_profile) but is not a valid one, for example because it has no Poppy act. The SDK refuses it rather than store an anonymous subject as a user session. error.reason names the failing check; it is logged on the server and never part of the message.

    • Defined in src/errors/poppy-errors.ts:18

    NOT_ENABLED

    NOT_ENABLED: "poppy_not_enabled"

    Client-side poppy.getContext(): the context route answered 404, so the poppy option is not set on the server or the route is not mounted.

    • Defined in src/errors/poppy-errors.ts:47

    SIGN_IN_REQUIRED

    SIGN_IN_REQUIRED: "poppy_sign_in_required"

    A login was refused because an agent guest is driving this browser. Only a signed-in agent join, or a new guest join, may replace the guest. A person's login, or the same guest coming back, is refused. On Auth0 a guest's own login comes back as the same guest, so redirecting would loop. Logging out ends the guest, after which the person can sign in.
